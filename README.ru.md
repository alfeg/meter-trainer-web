# Тренер счётчика

[English](README.md) · **Русский**

Обучите модель цифр для **своего счётчика** прямо в браузере, на снимках счётчика
[AI-on-the-edge-device](https://github.com/jomjol/AI-on-the-edge-device).

Это одна HTML-страница (`trainer.html.gz`, ~370 КБ). Она собирает изображения цифр,
которые сохраняет устройство, размечает их, обучает модель цифр в браузере и
устанавливает int8-файл `.tflite`, который загружает прошивка. Страница открывается с
SD-карты устройства (`/html/trainer.html.gz`) или с диска. Ссылок на CDN нет, поэтому
она работает в сети без доступа в интернет. Прошивку менять не нужно.

## Установка

1. Скачайте `trainer.html.gz` из [последнего релиза](../../releases/latest).
2. В файловом менеджере устройства загрузите его в `/html/`.
3. Откройте `http://<устройство>/trainer.html`. Прошивка кеширует страницу на 12 ч,
   поэтому после обновления перезагрузите её принудительно (Ctrl+F5). Значок в шапке
   показывает, нашла ли страница устройство; если там «не на устройстве», нажмите на него:
   видно, что запрашивалось (`/statusflow`, до трёх попыток по 8 с) и что пришло в ответ,
   там же можно проверить снова.

Обучение идёт на видеокарте (WebGL): используйте браузер на компьютере. Размечать можно и
на телефоне (см. «Сохранить на устройство» ниже). Для сбора нужно несколько дней снимков
цифр, сохранённых устройством (шаг 1 это настраивает).

## Что делает страница (открытая с устройства)

Мастер: «Начало» (обзор, автоматический запуск) и пять шагов, каждый доступен в любой момент.

1. **Настройка устройства:** читает `config.ini` и проверяет, что изображения цифр
   сохраняются (`ROIImagesLocation`) и хранятся достаточно долго (`ROIImagesRetention`).
   Исправляется одной кнопкой: конфигурация сохраняется в `/config/config_<ts>.ini.bak`,
   новая записывается сразу после цикла считывания (с проверкой MD5), и устройство
   перезагружается.
2. **Сбор:** сначала проверка просматривает новые папки `/log/digit/<день>/<час>/` (с
   оценкой оставшегося времени) и показывает, сколько изображений предстоит загрузить и
   сколько это займёт; затем кропы сохраняются в IndexedDB («Найти и загрузить» в меню
   кнопки делает оба шага сразу). Показание устройства записано в имени каждого файла; кропы
   группируются по барабану и показанию (цифра, положение между двумя цифрами, отклонённое
   показание), и в каждой группе хранится «изображений на значение» (по умолчанию 100),
   равномерно по часам, когда оно встречалось, — старые и новые дни, день и ночь; следующий
   сбор загружает только то, что заполняет новые часы; уже собранное не удаляется. Сбор можно
   продолжить после остановки; завершённые часы запоминаются. Можно также импортировать
   zip с размеченным набором.
3. **Разметка:** источники — показание устройства, неподвижные серии (≥4 одинаковых
   показания подряд), ИИ-сервер (Ollama `/api/chat` или OpenAI-совместимый
   `/v1/chat/completions`) и ваша проверка. Два согласных источника — метка подтверждена.
   По умолчанию обучение идёт только на ваших и подтверждённых метках. Таблица покрытия и
   оценка готовности показывают, чего не хватает. В сетке проверки можно размечать с
   клавиатуры, а на телефоне — касаниями; изображения, на которых училась последняя модель,
   отмечены (●), а нарисованные примеры показывают, как размечать барабан между цифрами
   (одна цифра видна целиком — эта цифра; обе обрезаны — «между»).
4. **Обучение:** в Web Worker (продолжается в фоновой вкладке). Тестовая выборка — самые
   новые ~20% каждой пары «барабан + метка», так что проверяется каждая метка, включая
   положения между цифрами; почти одинаковые убраны, не больше 50 на пару. Результаты — по
   барабанам и по меткам. На каждый барабан и значение обучается до 300 изображений, равномерно по
   времени и без почти одинаковых; меньшие группы повторяются (до 4 раз), чтобы каждая
   весила примерно одинаково. Новая модель сравнивается с установленной на тех же тестовых изображениях,
   которые прочитало устройство, и только если их не меньше 100. Тестовые изображения, на
   которых новая модель ошиблась, показываются списком, начиная с самых уверенных ошибок
   (часто это неверная метка), и открываются в проверке.
5. **Установка:** загружает модель в `/config/`, переключает `[Digits] Model` после
   цикла, перезагружает устройство и ждёт первого показания; отмена одной кнопкой. «Показать её
   изображения» открывает в новой вкладке страницу со всеми изображениями, на которых училась
   модель, и тестовыми; ошибки модели для сравнения — красным. Модель можно скачать и
   zip-архивом с изображениями, на которых она училась, тестовыми и
   `index.html` — одной страницей со всеми ними по меткам или по барабанам и меткам.

**Автоматический запуск** выполняет шаги 2–5 подряд и устанавливает модель, только если
она не хуже текущей на тех же изображениях.

**Сохранить на устройство / Загрузить с устройства** (шаги «Сбор» и «Разметка») хранят всё
состояние (изображения, метки, собранные папки) на SD-карте:
`/config/trainer-state.zip` (метки и список изображений) и JPEG частями до 7 МБ — устройство
принимает файлы не больше 8000 КБ. Загрузите его в другом браузере, например на телефоне, и
продолжайте разметку там. При загрузке добавляются недостающие изображения, а для каждого
изображения остаётся более новая метка.

## Сборка

Node 22:

```bash
npm ci
npm run build          # -> dist/trainer.html и dist/trainer.html.gz
npm run check:i18n     # у каждого английского текста есть русский
DEVICE=http://<ip-устройства> npm run dev   # dev-сервер; проксирует API устройства
```

Прошивка отдаёт `trainer.html.gz` с `Content-Encoding: gzip` при запросе `/trainer.html`,
поэтому на карту кладётся только `.gz`.

## Структура кода

Страница на Vue 3 (однофайловые компоненты `<script setup>`, без библиотеки хранилищ):

```
src/
  main.js, App.vue   точка входа и оболочка (заголовок, панель шагов, раздел на каждый шаг)
  views/             по экрану на шаг: StartView … InstallView
  components/        Base* = общие части (строка статуса, журнал, полоса прогресса, кроп);
                     labels/Labels*, train/Train* = части одного экрана; StepPill, StepNav
  stores/            общее состояние и действия, без разметки (см. ниже)
  services/          всё вне страницы: HTTP API устройства, IndexedDB (db.js), ИИ-сервер,
                     сборщик изображений с устройства
  lib/               чистая логика, её запускают и скрипты Node: набор данных, метки,
                     готовность, обучающая выборка, модель, экспорт TFLite (lib/tflite/)
  workers/           train.worker.js: обучение TensorFlow.js вне основного потока
  i18n/              t() / tHtml() (index.js), русские тексты (ru.js), подсказки (hints.js)
  plugins/           hintTooltip.js: общая всплывающая подсказка для элементов [data-hint]
  utils/             форматирование, md5
  assets/            main.css (все стили), шрифты
```

- Хранилища: `app.js` — открытый шаг, единственная выполняемая задача (`runTask`), строки
  статуса и метки шагов; `project.js` — кропы и метки; дальше по одному на шаг (`setup`,
  `collect`, `ai`, `review`, `train`, `install`, `auto`, `datasetExport`, `deviceState`,
  `modelExport`).
  Кропов и меток много, поэтому `project.js` держит их вне реактивности Vue и увеличивает
  счётчик `rev` при изменениях.
- Импорты: `@/` (= `src/`) в компонентах и хранилищах; `lib/`, `services/`, `i18n/` и
  `utils/` импортируют друг друга относительными путями, чтобы скрипты Node
  (`scripts/node-check.mjs`) загружали их без Vite.

Тексты: везде `t("English text", vars)`, `tHtml(key, html)` для текста с разметкой и
`N_("...")` для английского текста в данных; `node scripts/i18n-keys.mjs` показывает,
чего не хватает в `src/i18n/ru.js`.

## Zip с набором данных

```
labels.csv     path,src,pos,label,split,ts
images/...     JPEG-кропы (любого размера; уменьшаются до 20x32 билинейно, как в PIL)
```

`label` — цифра (`7`) или, для барабана между двумя цифрами, обе цифры (`7/8`, обучается
как 0.5/0.5). `split` — `train` или `test`; тестовые кропы используются только для таблицы
результатов. `scripts/make_dataset_zip.py` упаковывает набор, подготовленный в другом месте:

```bash
python scripts/make_dataset_zip.py dataset_meta.csv dataset.zip
```

## Модель и экспорт

- **Сеть:** пресет «small» соответствует установленной модели f24 (свёртки 24/48/48,
  полносвязные 128/64, около 3 млн умножений-сложений на цифру).
  - Каждый свёрточный блок: Conv3x3 → BatchNorm → LeakyReLU(0.3) → MaxPool.
  - BatchNorm и масштаб входа (1/255) при экспорте встраиваются в веса свёрток.
- **Экспорт** (`src/lib/tflite/export.js` + `writer.js`): flatbuffer TFLite пишется напрямую.
  - Операции: QUANTIZE, CONV_2D, LEAKY_RELU, MAX_POOL_2D, RESHAPE, FULLY_CONNECTED,
    SOFTMAX, DEQUANTIZE. Все есть в `CTfLiteClass::MakeStaticResolver`.
  - Квантование: int8 веса свёрток по каналам, веса полносвязных слоёв на тензор, смещения
    int32, активации откалиброваны на 300 обучающих кропах.
  - Вход и выход остаются float32, как у штатных моделей `dig-cont` (DoubleHyprid10,
    10 выходов).
- **Имя файла:** `dig-cont_<yyyymmddhhmm>_f<фильтры>_n<изображения>_q.tflite` (время UTC,
  число фильтров первой свёртки, число изображений обучения), в порядке полей штатных
  моделей (`dig-cont_0900_s3_q.tflite`). Пример: `dig-cont_202610161419_f24_n19359_q.tflite`.

## Ограничения браузера на страницах `http://<устройство>`

Такие страницы не считаются безопасным контекстом, поэтому:
- Нет WebGPU: обучение идёт через WebGL.
- Нет выбора папки: проект хранится в хранилище браузера, а переносится zip-файлами или
  через «Сохранить на устройство».
- Нет `crypto.subtle`.
- WebAssembly работает в один поток, потому что прошивка не отправляет заголовки COOP/COEP.
